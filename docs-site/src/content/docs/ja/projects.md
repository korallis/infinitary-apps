プロジェクトとは、乗組員が作業する対象です。git で管理している自分のフォルダです。
どのタスクもいずれかのプロジェクトに属し、タスクキーは `WEB-12` のように、そのプロジェクトのキーで始まります。
プロジェクトは **設定 → プロジェクト** に一覧表示されます。

## プロジェクトを追加する {#add-a-project}

プロジェクトを追加する方法は 2 つあります。

- **一等航海士に頼む。**
  どのプロジェクトで作業するかを伝えます。たとえば「次のプロジェクトをクローンして」と書き、そのリンクを続けます。
  一等航海士が、プロジェクトとその設定を示したカードを持ってきます。
  そのカードで **プロジェクトを追加** を押すまで、何も追加されません。
- **自分で追加する。**
  **設定 → プロジェクト** を開き、一覧のいちばん下にある **プロジェクトを追加** の行を使います。

**プロジェクトを追加** の行には 3 つのボタンがあります。

1. **このコンピューターのフォルダ** は、すでに手元にあるフォルダを追加します。
   そのフォルダでまだ git を使っていない場合は、Infinitary がそこで git を開始し、空の最初のコミットを作成します。
2. **GitHub のリポジトリ**、**GitLab のリポジトリ**、**Bitbucket のリポジトリ** は、プロジェクトをその保管先からクローンします。
   **あなたの GitHub リポジトリ** から選ぶか、**リポジトリを検索** で探すか、リンクを貼り付けます。
   リポジトリが多い場合は、すべてを確認できないことがあり、そのときは一覧にそう表示されます。見つからないリポジトリは、リンクを貼り付けて追加してください。
3. **新しいプロジェクト** は、入力した名前で空のプロジェクトを始めます。

クローンしたプロジェクトや新しいプロジェクトは、プロジェクトのフォルダに入ります。
**新しいプロジェクトの保存先** の行にそのフォルダが表示され、**フォルダを選択** で変更できます。
変更しても、すでに追加したプロジェクトが移動することはありません。

**タスクキー** の入力は任意です。
英字か数字を 4 文字まで入力すると、次に追加するプロジェクトのタスクにはそのキーで番号が付きます。
空のままにすると、Infinitary がプロジェクトの名前からキーを作ります。

ほかのホストにあるプロジェクトについては、一等航海士に頼んでください。

## GitHub、GitLab、Bitbucket へのサインイン {#your-github-gitlab-or-bitbucket-sign-in}

プロジェクトをクローンし、その変更を提出するために、Infinitary は GitHub、GitLab、Bitbucket へのサインインを使います。

**GitHub のリポジトリ**、**GitLab のリポジトリ**、**Bitbucket のリポジトリ** を押したときにサインインしていなければ、行にはプロジェクトの代わりに **GitHub にサインイン**、**GitLab にサインイン**、**Bitbucket にサインイン** が表示されます。
このボタンを押すと、サインインを管理する **設定 → 連携** が開きます。[連携](/ja/integrations/)を参照してください。
GitHub の場合は、ブラウザで開いた GitHub のページにコードを入力します。
GitLab の場合は、gitlab.com でも自分の GitLab サーバーでも、ブラウザでサインインするか、キーを貼り付けられます。
Bitbucket の場合は、bitbucket.org のプロジェクトについて、Atlassian アカウントで API トークンを作成して貼り付けます。
キーの入力欄には、Atlassian のページでチェックを入れるスコープが示されています。
自分の Bitbucket Data Center サーバー（バージョン 8.19 以降）の場合は、そのアドレスを入力し、Project read と Repository write の権限を持つ HTTP アクセストークンを貼り付けます。
Data Center のプロジェクトの変更はプルリクエストとして提出され、マージはあなたが承認したバージョンでのみ行われます。その間に誰かがプッシュした場合は何もマージされず、タスクにそう表示されます。
Data Center のプロジェクトでも一括プルリクエストを選べます。乗組員はサーバー上で読み書きし、あなたのフォークを通じて貢献し、プルリクエストへの新しいコメントやメインブランチでの失敗したチェックで起動します。
Data Center サーバーは独自のチェックログ、実行、リリースファイルを持ちません。チェックは別のサービスから届き、それぞれにログの場所へのリンクがあります。
Bitbucket のプロジェクトは、自分が所属しているワークスペースから一覧表示されます。ワークスペースが多い場合はすべてを確認できないことがあり、そのときは一覧にそう表示されます。
Bitbucket のプロジェクトの変更も、GitHub や GitLab と同じくプルリクエストとして提出されます。以前に追加したプロジェクトも、次のタスクから同じように動きます。
Bitbucket のプルリクエストの説明には変更の説明がテキストで入り、画像はカードに残ります。
Bitbucket のプロジェクトでは一括プルリクエストも選べ、マージは bitbucket.org でそのメインブランチに設定されたマージ方法とマージキューに従います。
Bitbucket のプロジェクトでも、GitHub や GitLab と同じく、乗組員はプロジェクトのパイプラインとステップのログを読み、リリースファイルを Downloads に置き、プルリクエストへの新しいコメントで作業を再開できます。ただし、Bitbucket ではパイプラインの成果物はダウンロードできません。
サインインはこのコンピューターに保存されます。

サインインが使えなくなったときは、カードがもう一度サインインするよう求めます。
サインインが必要な作業は、サインインするまで待機します。

## 作業コピー {#working-copies}

乗組員がプロジェクトのフォルダで直接作業することはありません。
乗組員はそれぞれ、プロジェクトの専用の作業コピーで、専用のブランチを使って作業します。
変更をマージするまで、手元のファイルはそのまま変わりません。

## 1 つのプロジェクトに絞り込む {#focus-on-one-project}

プロジェクトが 2 つ以上あると、上部のバーにプロジェクトのボタンが表示されます。
それを押すか、⇧⌘P （Linux と Windows では Ctrl+Shift+P ）を押すと、プロジェクトの列が開きます。
各ボタンには、あなたを待っているタスクの数と作業中のタスクの数が表示されます。
プロジェクトを選ぶと、ウインドウがそのプロジェクトに絞り込まれます。

プロジェクトに絞り込んでいる間は、次のようになります。

- タスクパネルとタスクボードには、そのプロジェクトのタスクだけが表示されます。
- アクティビティには、そのプロジェクトに関する行と、どのタスクにも関係しない行だけが表示されます。
- ほかのプロジェクトに関するカードは、絞り込みが変わるまで待機します。
  何も閉じられず、どのプロジェクトからも引き続き通知が届きます。
- ボタンの横には、ほかのプロジェクトであなたを待っているタスクの数が「ほかで 2 件待機中」のように短く表示されます。
- 新しく頼んだ作業は、別のプロジェクトを指定しない限り、一等航海士がそのプロジェクトに入れます。

ボタンの横の **×** （**すべてのプロジェクトを表示**）を押すか、列で **すべてのプロジェクト** を選ぶと、またすべてが表示されます。
Infinitary を再起動しても、絞り込みは記憶されています。

## 変更がプロジェクトに届く方法 {#how-changes-reach-your-project}

**設定 → プロジェクト** でプロジェクトを開くと、完成した作業をどのようにマージするかを選べます。
**変更の届け方** には次の選択肢があります。

- **プルリクエスト**：変更ごとに、GitHub、GitLab、Bitbucket でプルリクエストとして提出します。
- **一括プルリクエスト**：承認した変更を、変更ごとに 1 つのコミットにして 1 つの一括プルリクエストにまとめ、チェックに合格したらマージします。
- **ローカルマージ**：プルリクエストを使わず、このコンピューター上のプロジェクトに変更をマージします。

このコンピューターにしかないプロジェクトでは、**ローカルマージ** だけを選べます。

変更の準備ができると、担当の乗組員がマージカードを持ってきます。
カードのボタンには、**プルリクエストをマージ**、**ブランチをマージ**、**次の一括プルリクエストでマージ** のように、何をするかが書かれています。
チェックがまだ実行中のときは、ボタンが **チェックに合格したらマージ** になり、チェックに合格した時点で Infinitary がマージします。

**マージ前に確認** は、誰がマージするかを決めます。
新しいプロジェクトではオンになっているので、完成した作業はあなたの返事を待ちます。
オフにすると、チェックに合格した作業は確認なしにマージされることがあります。

**慎重さ** は、作業をどれだけ念入りに確認するかを **クイック**、**標準**、**慎重** から設定します。

## プロジェクトを削除する {#remove-a-project}

1. **設定 → プロジェクト** でプロジェクトを開きます。
2. いちばん下の行にある **削除** を押します。
3. もう一度 **削除** を押して確定します。

削除すると、プロジェクトが一覧から外れます。
フォルダと完了したタスクはそのまま残ります。
まだタスクが残っている場合は、Infinitary がそれを示すので、先に完了させるか取りやめてください。
