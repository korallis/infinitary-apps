專案就是你的船員工作的對象：一個屬於你、用 git 管理的資料夾。
每項任務都屬於一個專案，每個任務編號都以它所屬專案的前綴開頭，例如 `WEB-12`。
你的專案都列在 **設定 → 專案**。

## 加入專案 {#add-a-project}

加入專案有兩種方式。

- **請你的大副加入。**
  說出要處理哪個專案，例如「複製這個專案」再附上它的連結。
  你的大副會帶來一張卡片，寫明專案和它的設定。
  在你按下卡片上的 **加入專案** 之前，什麼都不會加入。
- **自己加入。**
  打開 **設定 → 專案**，使用清單最下方的 **加入專案** 這一列。

**加入專案** 這一列有三個按鈕：

1. **這台電腦上的資料夾** 會加入你已經有的資料夾。
   如果這個資料夾還沒有使用 git，Infinitary 會在裡面啟用 git，並建立一個空白的第一次提交。
2. **GitHub 存放庫**、**GitLab 存放庫** 或 **Bitbucket 存放庫** 會從專案所在處複製專案。
   從 **你的 GitHub 存放庫** 裡挑選、用 **尋找存放庫** 搜尋，或貼上它的連結。
   存放庫很多時，可能有些沒有被讀到，清單會註明這一點；要加入缺少的存放庫，貼上它的連結即可。
3. **新專案** 會用你輸入的名稱建立一個空白專案。

複製的專案和新專案會放進你的專案資料夾。
**新專案存放在** 這一行會顯示那個資料夾，**選擇資料夾** 可以更換它。
更換資料夾時，你已經加入的專案不會搬動。

**任務編號前綴** 可以不填。
輸入最多四個字母或數字，下一個專案的任務就會用它來編號。
如果留空，Infinitary 會依專案名稱產生前綴。

如果專案放在其他主機上，請問你的大副。

## 你在 GitHub、GitLab 或 Bitbucket 的登入 {#your-github-gitlab-or-bitbucket-sign-in}

要複製專案並提出它的變更，Infinitary 會使用你在 GitHub、GitLab 或 Bitbucket 的登入。

如果你按下 **GitHub 存放庫**、**GitLab 存放庫** 或 **Bitbucket 存放庫** 時還沒有登入，這一列會顯示 **登入 GitHub**、**登入 GitLab** 或 **登入 Bitbucket**，而不是你的專案。
這個按鈕會打開 **設定 → 整合**，你的登入都在那裡；請參閱[整合](/zh-hant/integrations/)。
GitHub 的話，你要在瀏覽器裡的 GitHub 頁面輸入一組代碼。
GitLab 的話，你可以在瀏覽器裡登入，或貼上金鑰，gitlab.com 或你自己的 GitLab 伺服器都可以。
Bitbucket 的話，你要在 Atlassian 帳號上建立一個 API token 並貼上，適用於 bitbucket.org 上的專案。
金鑰表單會列出你要在 Atlassian 頁面上勾選的權限範圍。
如果是你自己的 Bitbucket Data Center 伺服器（8.19 或更新版本），你要輸入它的位址，並貼上一個具有 Project read 和 Repository write 權限的 HTTP 存取權杖。
Data Center 專案的變更會以 pull request 提出，而且只會在你核准的版本上合併：如果有人在這段期間推送，就不會合併任何東西，任務也會註明這一點。
Data Center 專案也可以選擇批次 pull request，你的船員可以在伺服器上讀寫、透過你的 fork 貢獻，並在它的 pull request 有新留言、主要分支上有檢查失敗時被喚醒。
Data Center 伺服器沒有自己的檢查記錄、執行紀錄或發行檔案：它的檢查來自另一個服務，每個檢查都會連到記錄所在的位置。
你的 Bitbucket 專案會從你所屬的工作區列出；工作區很多時，可能有些沒有被讀到，清單會註明這一點。
Bitbucket 專案的變更會以 pull request 提出，和 GitHub、GitLab 一樣；在這之前加入的專案，從它的下一項任務起也會這樣運作。
Bitbucket pull request 的說明會以文字承載變更故事，圖片則留在卡片上。
Bitbucket 專案也可以選擇批次 pull request，它的合併會遵循它在 bitbucket.org 上主要分支的合併策略和合併佇列。
在 Bitbucket 專案上，船員也能讀取專案的 pipeline 和某個步驟的記錄、把發布檔案放進它的 Downloads，並在它的 pull request 有新留言時醒來，和 GitHub、GitLab 一樣；Bitbucket 不提供下載 pipeline 的成品。
你的登入只留在這台電腦上。

如果某個登入失效了，會有一張卡片請你重新登入。
需要這個登入的工作會等到你登入為止。

## 工作副本 {#working-copies}

你的船員從不直接在你的專案資料夾裡工作。
每位船員都在自己的專案工作副本裡、在自己的分支上工作。
在你合併變更之前，你的檔案都會維持原樣。

## 聚焦在一個專案 {#focus-on-one-project}

有兩個以上的專案時，頂端列會顯示一個專案標籤。
按一下它，或按 ⇧⌘P（Linux 上是 Ctrl+Shift+P），就會打開一列你的專案。
每個標籤都會計算等你處理的任務數和進行中的任務數。
選一個專案，讓視窗聚焦在它上面。

聚焦在一個專案時：

- 任務面板和任務看板只顯示這個專案的任務。
- 動態只顯示和這個專案有關的內容，以及不屬於任何任務的內容。
- 其他專案的卡片會等到聚焦改變後再出現。
  不會有任何東西被關閉，每個專案也照樣會傳送通知。
- 標籤旁的一行短字會告訴你其他地方有幾項任務在等你，例如「其他地方有 2 項等你處理」。
- 你交代的新工作，大副會放進這個專案，除非你指定別的專案。

按下標籤旁的 **×**（**顯示所有專案**），或在那一列裡選 **所有專案**，就能再看到全部內容。
Infinitary 重新啟動後會記得你的聚焦設定。

## 變更如何進入你的專案 {#how-changes-reach-your-project}

在 **設定 → 專案** 打開一個專案，就能選擇完成的工作要怎麼合併。
**變更去向** 提供這些選項：

- **pull request**：每個變更都會在 GitHub、GitLab 或 Bitbucket 上以 pull request 提出。
- **批次 pull request**：你核准的變更會合成一個批次 pull request，每個變更各一個提交，並在檢查通過後合併。
- **本機合併**：變更會直接合併到這台電腦上的專案，不經過 pull request。

只存在這台電腦上的專案只提供 **本機合併**。

變更準備好時，負責的船員會帶來一張合併卡片。
卡片上的按鈕會說明它做什麼，例如 **合併 pull request**、**合併分支** 或 **隨下一個批次合併**。
如果檢查還在執行，按鈕會顯示 **檢查通過後合併**，檢查一通過 Infinitary 就會合併。

**合併前先問過你** 決定由誰來合併。
新專案預設開啟這個設定，所以完成的工作會等你同意。
關閉它之後，通過檢查的工作可以不問你就合併。

**謹慎度** 設定工作要檢查得多仔細：**快速**、**預設** 或 **謹慎**。

對變更透過 pull request 進入的專案，**說明 AI 協助** 預設開啟。
船員審查他人的 pull request 時，發布的留言以一行說明由 Infinitary 船員撰寫的文字開頭。
修改這一行並按 **儲存**，或關閉開關不加這一行。

## 移除專案 {#remove-a-project}

1. 在 **設定 → 專案** 打開這個專案。
2. 按下最後一行的 **移除**。
3. 再按一次 **移除** 確認。

移除只會把專案從清單上拿掉。
它的資料夾和已完成的任務都會保留。
如果專案還有任務，Infinitary 會列出來，你要先完成或放棄它們。
